パッケージは1つ、ターゲットフレームワークも1つ、ホスティング方式に選択肢はありません。このページ
は、何を入れるかと、何を Blazor に任せているかです。

## インストール

```
dotnet add package BlazorCodeFirst --prerelease
```

公開しているバージョンには prerelease の接尾辞が付いています。`--prerelease` を外すと最新の安定版
を探しに行き、それは存在しないので何も解決しません。

1つのパッケージが両方を運びます。ランタイムは `lib/net10.0` に、ジェネレーターとアナライザーは
`analyzers/dotnet/cs` に入っています。追加するパッケージは他にありません。

## 必要なもの

- .NET SDK 10.0.100 以降。
- IDE を使うなら Visual Studio 2026 バージョン 18.0 以降。

ジェネレーターは Roslyn 5.0 のアナライザーとして配られ、それより古いコンパイラは読み込みを拒み
ます。

ターゲットフレームワークのベースラインは `net10.0` で、全機能を備えています。

## ホスティング方式はこのライブラリが決めるものではありません

あなたのコンポーネントは、ふつうの `ComponentBase` 派生クラスの `RenderView` オーバーライドへ
コンパイルされます。Blazor はそれを Razor コンポーネントと同じように差分計算します。Server、
WebAssembly、静的なサーバーサイドレンダリングは `.razor` の場合と同じように動き、方式ごとの設定
は要りません。

このドキュメントサイト自体が実例です。WebAssembly アプリをビルド時にプリレンダリングし、静的
ファイルとして配信しています。

## レンダーモードを指定する

呼び出しサイトから、呼ぶコンポーネントのレンダーモードを指定できます。

```csharp
Component<Counter>().RenderMode(RenderMode.InteractiveWebAssembly)
```

この形は、自分ではモードを宣言しないコンポーネントのためにあります。必要になるのはその場合です。
同じコンポーネントを、あるページからは対話的に、別のページからは静的に描くときです。自身の宣言
でモードを固定しているコンポーネントは、呼び出しサイトからの指定を拒みます
（[BCF3034](./diagnostics.md#bcf3034)）。

## トリミングして配信する

実行時の UI ツリーはなく、リフレクションもなく、式のコンパイルもありません。だからトリミングの
ルートも AOT のヒントも要りません。コンポーネントを書いた設計時の API は、ビルドを生き延びること
すらしません。ジェネレーターがその構文を読み、IL トリマーが本体を削ります。

測ってある唯一のコストはバインドで、バインドごとではなく一度きりです。
[双方向バインド](./two-way-binding.md#トリムして配布する場合)を読んでください。
